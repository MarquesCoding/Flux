# ADR-0021: FluxUI is rebuilt from the shadcn registry, on Base UI

- **Status:** Accepted
- **Date:** 2026-08-18
- **Deciders:** Marques Scripps
- **Supersedes:** [0018](0018-fluxui-on-radix-and-shadcn-conventions.md), for its
  primitive and its registry clause
- **Superseded by:** —

## Context

[ADR-0018](0018-fluxui-on-radix-and-shadcn-conventions.md) decided two things
that this reverses, and one that it keeps.

It chose **Radix** over Base UI, knowing Base UI was the better library, because
the ecosystem's shared vocabulary — every animation recipe worth borrowing — was
written against Radix's `data-[state]` attributes. And it refused **the
registry**: "No component is generated by the shadcn CLI. Each is written by
hand against this repository's rules." It even named the risk it was guarding
against: "the temptation will be to paste from the registry when a new component
is needed."

Two things have changed since.

**Dialogs do not animate closed.** Every recipe 0018 traded Base UI away for says
this should work: `data-[state=closed]:animate-out` with `tw-animate-css`, which
is exactly what FluxUI's `Dialog` does. It has never worked here. The built CSS
was verified complete — the exit keyframes, the leaving duration, the
closed-state variables all present — and the component checked structurally
against shadcn's own Radix version, which it matches. The cause was not found.
What was learned along the way is that the environment cannot arbitrate it: a
jsdom probe of Radix's `Presence` reported instant unmount even for bare Radix,
so it was discarded rather than concluded from.

The ecosystem vocabulary 0018 paid for is therefore not being collected. Base UI
has a working exit animation and is the Radix team's own successor.

**Fifty-three components is not a base.** What FluxUI has is what the
application has so far needed. The registry has sixty-three, including things
never built here — button groups, fields, input groups, a command palette, a
combobox, a sidebar, a sheet, a carousel, charts, resizable panes, pagination.
Hand-writing each on demand is how the last year went, and it front-loads a
design decision onto every new screen. Starting from a complete set and
restyling it inverts that.

## Decision

**FluxUI is rebuilt from the shadcn registry, generated by its CLI against Base
UI.** All sixty-three components land in `packages/ui/src/base`.

**The old components are moved, not deleted.** The fifty-three hand-written
components live in `packages/ui/src/old` with every `@FluxUI/*` alias repointed,
so the eighty-eight files in the web app that import them are untouched and the
application runs exactly as before. Nothing is removed until the thing replacing
it is in place.

**The generated layer is a quarantine.** `src/base` carries its own ESLint and
oxlint overrides for the rules registry code cannot satisfy — one member per
file, TSDoc on functions, type assertions, `unknown`, raw controls, loose
equality — and is excluded from coverage so untested generated code cannot prop
up or drag down a threshold that is meant to measure written code.

**A component leaves quarantine by being restyled.** That is when it is rewritten
to house standard — one member per file, a `.types.ts`, TSDoc, a co-located test
— and moves to `src/components`. Quarantine is a staging area with an exit, not
a second standard.

**Two of 0018's rules are kept, and enforced against the generated code rather
than waived for it.**

- _Icons._ The registry imports from Lucide, which [ADR-0020](0020-icons-from-hugeicons-through-one-component.md)
  bans precisely so a second set cannot return a file at a time.
  `base/icons.tsx` gives those imports somewhere else to land, drawing sixteen
  glyphs through `@FluxUI/Icon`. Only the import line changes in each file, so a
  regenerated component does not undo it and six hundred call sites still resolve
  to one icon set.
- _`accent`._ 0018 ruled that the brand keeps the name and shadcn's subtle-hover
  role is `subtle`. That still holds, so the generated markup is remapped onto
  `subtle` rather than the token being redefined under fifty-three components
  that depend on it. This is not pedantry: `muted` resolves to `surface-raised`,
  which is already the popover background, so a hover painted `muted` would have
  been invisible on exactly the five menu components that use it.

## Consequences

### What this gets us

Dialogs can close visibly, and the next thing that needs an exit animation is a
recipe rather than an investigation.

A complete set to design against. The next screen that wants a command palette
or a field group has one to restyle instead of one to invent.

Regeneration is now a real option. A component that has not been restyled yet
can be pulled again from the registry to pick up upstream fixes, because nothing
about it has been hand-edited except its import lines.

### What this costs us

**Two component libraries in the tree at once**, and they will coexist for as
long as the restyle takes. Every screen still renders `old`; `base` renders
nothing until it is adopted. Someone reading `packages/ui` has to know which is
which, and the risk is that `old` becomes permanent by neglect.

**Nothing in `base` is tested.** Sixty-three components with no co-located tests,
excluded from coverage. That debt is real and is only paid down component by
component, as each is restyled.

**The Radix vocabulary 0018 chose is now the wrong one** for the new layer, and
`old` still speaks it. Animation work is against two different attribute
conventions until the migration finishes.

**Dependencies arrived that nothing yet uses** — `cmdk`, `embla-carousel-react`,
`react-day-picker`, `react-resizable-panels`, `input-otp`, `date-fns`,
`next-themes`. They are tree-shaken out of the bundle, which is unchanged at
597 kB, but they are in the lockfile and `next-themes` in particular exists only
because the registry's Sonner wrapper reaches for it.

**The reversal itself is a cost.** This is the third decision about FluxUI's
primitive: 0013 chose Base UI, 0018 chose Radix, this chooses Base UI. The
churn is the evidence that 0018's tradeoff was made on a benefit that did not
materialise, but it is churn.

### What this forecloses

Nothing that was open. `old` remains a working library for as long as it takes,
and no screen is forced to move before the component it needs has been restyled.

## Alternatives considered

**The registry's Radix flavour.** `shadcn init -b radix` would have kept the
existing primitive, let `old` stay useful as reference, and ported some logic
mechanically. It also inherits the exact dialog behaviour that prompted this,
which is the one thing that had to change.

**Normalise all sixty-three up front.** Split every generated file into
one-member-per-file with types, TSDoc and tests before anything ships. Nothing
bends and there is no quarantine to exit — at the price of several hundred
hand-written files before a single screen can be looked at.

**Amend the standards permanently** so the registry's shape is the house shape:
multiple members per file, no per-component test. One ADR and no migration, but
it trades the rules that make this codebase legible for the convenience of not
rewriting generated code, forever.

**Keep hand-writing components.** What 0018 decided. It is defensible and it
produced a good library; it does not answer the dialog and it makes every new
screen pay for the component it needs.

## Revisit when

`src/old` is empty, at which point the quarantine and this ADR's coexistence
costs are spent and the layout should collapse back to one directory.

`src/old` has stopped shrinking. If components stop leaving quarantine, the
honest options are to finish it deliberately or to admit the base is not being
adopted and delete it.
