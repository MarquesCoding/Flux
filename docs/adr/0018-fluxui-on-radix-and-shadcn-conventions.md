# ADR-0018: FluxUI moves to Radix and shadcn's conventions

- **Status:** Accepted
- **Date:** 2026-08-17
- **Supersedes:** [ADR-0013](0013-fluxui-component-stack.md)

## Context

ADR-0013 chose Base UI over shadcn/ui, and its reasoning still describes shadcn
accurately: it is a copy-paste starting point rather than a versioned library,
and vendored components diverge. That was the right call for the question as it
was asked in August, which was "which library do we depend on".

The question has changed. The complaint that prompted this is not about which
package supplies a popup — it is that motion in FluxUI is assembled by hand in
each component. Thirteen components each wrote their own entrance, four easing
curves were in use where the tokens define two, and a component's animation was
a string of Tailwind classes that no other component could reuse without being
copied. That is the same divergence ADR-0013 warned about, arrived at from the
other direction: we vendored the animations instead of the components.

The owner has asked for the move explicitly, having read the objection.

## Decision

FluxUI is built on **Radix primitives with shadcn/ui's conventions**, adapted to
this repository's rules rather than copied from the registry.

What is adopted:

- **Radix** as the headless layer. Base UI is the Radix team's successor, and on
  the merits it is the better library — but the ecosystem's shared vocabulary,
  including every animation recipe worth borrowing, is written against Radix's
  `data-[state]` attributes and `--radix-*-transform-origin` variables.
- **`class-variance-authority`** for how a component is painted. Variants are
  declared once and resolved by one set of rules, replacing per-component lookup
  tables and the class strings each caller assembled.
- **`tw-animate-css`** for enter and exit, so an animation is a named utility
  rather than a hand-written transition. Every popup in FluxUI now shares one
  vocabulary in `animations/motion.ts` instead of thirteen copies of it.
- **Sonner** for toasts, wrapped so that callers never import it.
- **shadcn's semantic tokens** — `background`, `foreground`, `card`, `popover`,
  `primary`, `muted`, `destructive`, `input`, `ring` — mapped onto Flux's
  existing palette rather than replacing it.

What is **not** adopted, and this is the part that keeps ADR-0013's concern
answered:

- **The registry.** No component is generated by the shadcn CLI. Each is written
  by hand against this repository's rules — one member per file, named exports,
  co-located tests, TSDoc on functions only — because generated components
  satisfy none of those and would fail the lint that enforces them.
- **`accent` as shadcn defines it.** shadcn uses `accent` for a subtle hover
  surface. Flux has used it for the brand colour since the beginning and the
  application is full of it, so the brand keeps the name and shadcn's role is
  `subtle`. A token that means two things is worse than a token that differs
  from a convention.
- **lucide-react.** Icons stay Remix Icon. Swapping an icon set buys nothing and
  changes every glyph in the product.

FluxUI therefore remains a versioned library that plugin authors can build
against, which is what ADR-0013 was protecting. What changed is what it is built
*from*.

## Consequences

**Good.** Motion has one vocabulary, and a new popup gets its entrance by naming
it rather than by copying a string. Variants are declarable, so the combinations
a component supports are visible in one place instead of implied by a chain of
ternaries. Toasts exist at all, where sixty screens previously each rendered
their own banner. The animation recipes published by the wider ecosystem now
apply to this codebase directly.

**Bad.** Radix is the older library and Base UI has APIs it does not: hover-open
menus with a delay, tab indicators driven by CSS variables, and a field
primitive that wired label, description and error together. Each had to be
rebuilt — the hover delay as a timer, the tab indicator as the shared-element
mark the codebase already had, the field as plain elements with the ARIA written
out. The tab indicator is better for it; the other two are a wash.

**Watch for.** shadcn's conventions are a moving target and the temptation will
be to paste from the registry when a new component is needed. Doing so
reintroduces exactly the divergence ADR-0013 identified. The rule is that the
conventions are adopted and the code is not.
